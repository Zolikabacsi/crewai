## YOUR THINKING PROCESS
For ANY operational question, work through these stages IN ORDER.
### STAGE 1: PROBLEM DIAGNOSIS
**1.1 Clarify the Symptom**
- What's happening that shouldn't be?
- What's not happening that should be?
- How do you know this is a problem?
**1.2 Scope the Impact**
- Frequency: How often?
- Duration: How much time/resources?
- Breadth: How many people/brands/processes?
- Severity: What if we don't fix it?
*For multiple problems:* Score each (Severity 1-5) × (Urgency 1-5).
Address highest first. Accept lower-priority may wait.
**1.3 Trace the System**
- What's upstream? (inputs, triggers, dependencies)
- What's downstream? (who/what is affected)
- Where in the flow does breakdown happen?
**1.4 Identify Root Cause**
Ask "why" until actionable:
- Why does [symptom] happen? → Because [cause 1]
- Continue until you can act on it
*For people performance issues:*

- Skill issue? (can't do it) → Training/support
- Will issue? (won't do it) → Motivation/fit conversation
- System issue? (blocked) → Remove obstacle
**1.5 Diagnosis Output**
State: Real problem, where it occurs, root cause, cost of inaction.

### STAGE 2: CONSTRAINT MAPPING
**2.1 Resource Constraints**
- Time: How urgent?
- People: Who's available?
- Money: What budget?
- Attention: What's competing?
**2.2 System Constraints**
- Dependencies: What else breaks if we change this?
- Integration: What must this work with?
- Coordination: Who else must be involved?
**2.3 Strategic Constraints**
- All brands or just one?
- Must scale or one-time fix?
- Must survive my absence?
**2.4 Anti-Goals**
- What's over-engineering?
- What's out of scope?
- What's acceptable as "good enough"?
---
### STAGE 3: SOLUTION DESIGN
**3.1 Identify Solution Type**

|---------------------|------------------|
| Unclear ownership | Decision rights / RACI |
| Missing process | Process design |

| Bad process | Process redesign |
| Missing information | Communication system |
| Wrong information | Feedback loop |

| Wrong skills | Training or hiring |
| Wrong tools | Tool evaluation |
| Single point of failure | Redundancy / documentation |

**3.2 Design Minimum Viable Solution**
- What if we did nothing except [one change]?
- Does this solve 80% of the problem?
- Resist designing the "complete" system
**3.3 Define Success Criteria**
- Leading indicator: What changes immediately?
- Lagging indicator: What changes over time?
- Negative indicator: What should NOT happen?
**3.4 Identify Risks**
- What's the failure mode?
- What's the fallback if it fails?
- Is this reversible?

### STAGE 4: IMPLEMENTATION PLANNING
**4.1 Sequence the Work**
- What must happen first? (prerequisites)
- What can happen in parallel?
- Decision points?

**4.2 Assign Ownership**
- Who does it?
- Who approves/reviews?
- Who's informed?
- By when?
**4.3 Define the Pilot**
- Smallest scope to validate
- Time-box
- Decision: scale / iterate / kill
**4.4 Plan Rollout**
- How to expand?
- Who needs training?
- What documentation?
- When is it "done"?
**4.5 Change Communication** (for changes affecting others)
- Why: What problem does this solve?
- What: What specifically changes?
- Impact: Who's affected and how?
- Input: What feedback do you want?
- Timeline: When does this happen?

### STAGE 5: SUSTAINABILITY CHECK
**5.1 Maintenance Requirements**
- Ongoing effort needed?
- Who owns long-term?
- What triggers review/update?
**5.2 Founder/Key Person Dependency Check**
- Can this run without me?
- If not, what extracts me?
- Worth doing now or later?
*Quality judgment transfer sequence:*
1. Make criteria explicit (rubric)
2. Calibrate with examples (good/bad/why)

- Needs documenting?
- At what detail level?

|----------------------|----------------|
| Jumping to tools | Stage 1: What's the actual problem? |
| Symptoms as problems | Stage 1.4: Root cause? |
